# Плагин Token Seller для DeepSeek Harness

Пакет подключает DeepSeek Harness к сервису **Token Seller** (федота.рф):
вход по почте и паролю, получение ключа, баланс и история вызовов прямо в
настройках.

Здесь лежит **только собранный пакет**. Исходники живут отдельно и в этот
репозиторий не попадают.

## Установка

Пакет совместим со всей линейкой DeepSeek Harness `0.2`: подходит и `0.2.0-rc.2`,
и `0.2.1-rc.2`. На другой линейке харнесс откажет в установке.

Готовый архив: **https://федота.рф/download/plugins/fedot-token-seller-account-0.9.3.tgz**

1. Скачайте архив по ссылке выше и запомните, куда он попал (обычно «Загрузки»).
2. На панели слева, под **«Новой сессией»**, нажмите кнопку **«Плагины»**
   (на ней элемент пазла). Это не «Настройки» — раздел живёт на боковой панели.
3. Нажмите **«Добавить плагин»** и укажите **путь к скачанному файлу**:

   ```
   C:\Users\<имя>\Downloads\fedot-token-seller-account-0.9.3.tgz
   ```

   Именно путь к файлу на диске, а не адрес сайта. Распаковывать архив не нужно.
4. Нажмите **«Установить»** и перезапустите приложение.

Если в списке плагинов после установки ничего не появилось, проверьте, что
установился именно этот архив: в нём должны быть `cordis.patch.yml` и поле
`dsh.bundle` в `package.json`. Без них установка проходит молча, но плагин
не включается.

### Почему архив, а не ссылка на GitHub

Ссылка на репозиторий требует установленного **git**: менеджер плагинов
спрашивает у GitHub ссылки на ветки командой `git ls-remote`, и там, где git
нет, установка обрывается на первой же ошибке. Архив этого не требует: ни git,
ни доступа к GitHub.

### Установка из командной строки

То же самое без интерфейса, если удобнее:

```powershell
dsh plugin --profile <профиль> add "C:\Users\<имя>\Downloads\fedot-token-seller-account-0.9.3.tgz"
```

Профиль `desktop` принадлежит приложению, и командная строка его не примет.
В приложении пользуйтесь кнопкой **«Добавить плагин»**.

## Что происходит после установки

1. Откройте **Настройки** и найдите раздел **Token Seller**.
2. Войдите своей почтой и паролем от федота.рф.
3. Панель сама получит ключ, положит его в хранилище секретов под именем
   `TOKEN_SELLER_API_KEY` и пропишет маршрут моделей.

Штатный маршрут DeepSeek при этом **не выключается**: маршрут Token Seller
дописывается рядом. Если что-то с сервисом не так, чат продолжит работать на
штатном провайдере. Ключ настраивать руками не нужно, в поля он не выводится.

Все обращения к сервису идёт хост-половина пакета: браузер к Token Seller не
ходит.

## Что внутри

| Файл | Что это |
|---|---|
| `lib/index.js` | хост-половина: вход, ключ, баланс, все HTTP-вызовы к сервису |
| `lib/client.js` | браузерная половина: панель личного кабинета в настройках |
| `cordis.patch.yml` | слой, который вставляет пакет в дерево конфигурации |

Поле `dsh.bundle` в `package.json` делает пакет полноценным слоем. Благодаря
ему пакет ставится сам по себе, без общего сборочного слоя.

Адрес сервиса — настройка слоя. По умолчанию боевой домен
`https://xn--80ahc1bui.xn--p1ai` (`федота.рф`). Переменная окружения
`TOKEN_SELLER_BASE_URL` подменяет адрес на стенд при отладке.

## Ограничения

- **Обновления вручную.** Автоматических обновлений нет: чтобы поставить новую
  версию, пакет надо удалить и установить заново, взяв свежий архив по той же
  ссылке.
- **Нужен доступ к npm-реестру.** Пакет тянет из реестра две зависимости
  (`@deepseek-ai/dsh-anonymous-user-id` и `zod`). Без доступа к реестру
  установка упадёт. Git при этом не нужен: он требуется только ссылкам на
  GitHub, а не архиву.

## Сборка

Файлы в `lib/` собраны из исходников скриптом `scripts/build.mjs` в рабочем
репозитории модулей; переносит их туда `pnpm run release:account`. Здесь они
лежат готовыми: так ученику не нужны ни Node, ни pnpm, ни TypeScript. Карты
кода (`.map`) в репозиторий не положены: они весят больше самого кода, а
харнесс их отсутствие переносит.

Архив `fedot-token-seller-account-0.9.3.tgz` собирается из этого
каталога командой `pnpm pack` и лежит на витрине по адресу
`token-seller/static/plugins/fedot-token-seller-account-0.9.3.tgz`.
После обновления файлов в `lib/` архив нужно собрать заново и положить на
витрину — иначе со страницы установки по-прежнему будет скачиваться старая
сборка.
